# Unitree G1 の後転（シンプル版）

Gazebo の上で仰向けの G1 に後転させ、そのお手本を学習（ACT）し、学習したモデルで 2 回続けて後転させるまでの手順です。

- 作業フォルダ：`D:\dev\pai_ros2\pai_ros2`（コンテナの中では `/workspace`）

## 全体の流れ

1. ロボットを用意する：公式の G1 を Gazebo 用に変換し、**回転センサ**と**重り**を追加する
2. お手本を作る：キーポーズを順に再生して後転させる
3. データを集める：値を ±0.1 rad ずつ変えて 512 回試し、合格した 196 回だけ残す
4. 学習する：合格データを LeRobot 形式に変換し、ACT を GPU で学習する
5. 再生する：学習したモデルで 2 回続けて後転させ、録画する

| 追加したもの | 目的 |
|---|---|
| 回転センサ（OdometryPublisher） | 骨盤の姿勢から後転の角度を測る |

### 2.1 回転センサ

IMU ではなく、Gazebo の **OdometryPublisher**（骨盤の位置と姿勢をそのまま出すプラグイン）を使いました。

**追加の仕方**（`make_urdf.py`）

```python
gz_odom = ET.SubElement(robot, 'gazebo')
odom = ET.SubElement(gz_odom, 'plugin', {
    'filename': 'ignition-gazebo-odometry-publisher-system',
    'name': 'ignition::gazebo::systems::OdometryPublisher',
})
for key, value in [('odom_frame', 'odom'), ('robot_base_frame', 'pelvis'),
                   ('odom_publish_frequency', '50'), ('dimensions', '3')]:
    ET.SubElement(odom, key).text = value
```

**実際に追加された内容**（`g1_29dof_gazebo.urdf`）

```xml
<gazebo>
  <plugin filename="ignition-gazebo-odometry-publisher-system" name="ignition::gazebo::systems::OdometryPublisher">
    <odom_frame>odom</odom_frame>
    <robot_base_frame>pelvis</robot_base_frame>
    <odom_publish_frequency>50</odom_publish_frequency>
    <dimensions>3</dimensions>   <!-- 3 次元：傾きも出す -->
  </plugin>

```

**ROS 2 への受け渡し**（`g1_lying.launch.py` のブリッジ）

```python
'/model/g1/odometry@nav_msgs/msg/Odometry[ignition.msgs.Odometry'
```

**角度の計算**（`roll_trial.py`）：骨盤の四元数から「頭の向き」を求め、最初の向きを 0° として回転角を出します。

```python
def spine(qx, qy, qz, qw):          # 骨盤の「頭の向き」ベクトル（世界座標）
    return (2*(qx*qz + qy*qw), 2*(qy*qz - qx*qw), 1 - 2*(qx*qx + qy*qy))
# Roll：atan2(-上下成分, 前後成分) を 360° 単位でつないで連続にする
# 0° = 仰向け、90° = 肩で立つ、180° = うつ伏せ、360° = 1 回転して仰向け
```

### 2.2 重り（質量）

頭のてっぺんと両足の靴底に、各 2 kg（合計 6 kg）を足しました。
見た目と当たり判定のない「重さだけのリンク」を、固定関節で親リンクにつなぎます。Gazebo は固定関節のリンクを親にまとめるので、親リンクの質量と慣性がその分増えます。

**追加の仕方**（`make_urdf.py`）

```python
WEIGHTS = [  # (リンク名, 親リンク, 親から見た位置, kg, 箱 a×b×c m)
    ('right_shoe_weight', 'right_ankle_roll_link', '0.035 0 -0.01', 2.0, (0.16, 0.07, 0.02)),  # 靴底
    ('left_shoe_weight',  'left_ankle_roll_link',  '0.035 0 -0.01', 2.0, (0.16, 0.07, 0.02)),  # 靴底
    ('head_weight',       'head_link',             '0.005 0 0.43',  2.0, (0.10, 0.12, 0.15)),  # 頭のてっぺん
]
for wname, parent, xyz, kg, (a, b, c) in WEIGHTS:
    w = ET.SubElement(robot, 'link', {'name': wname})
    ine = ET.SubElement(w, 'inertial')
    ET.SubElement(ine, 'origin', {'xyz': '0 0 0', 'rpy': '0 0 0'})
    ET.SubElement(ine, 'mass', {'value': f'{kg}'})
    ET.SubElement(ine, 'inertia', {                       # 直方体の慣性
        'ixx': f'{kg * (b*b + c*c) / 12:.6f}', 'ixy': '0', 'ixz': '0',
        'iyy': f'{kg * (a*a + c*c) / 12:.6f}', 'iyz': '0',
        'izz': f'{kg * (a*a + b*b) / 12:.6f}'})
    j = ET.SubElement(robot, 'joint', {'name': wname + '_joint', 'type': 'fixed'})
    ET.SubElement(j, 'origin', {'xyz': xyz, 'rpy': '0 0 0'})
    ET.SubElement(j, 'parent', {'link': parent})
    ET.SubElement(j, 'child', {'link': wname})
```

**実際に追加された内容**（`g1_29dof_gazebo.urdf`。左足も右足と同じ）

```xml
<link name="right_shoe_weight">
  <inertial>
    <origin xyz="0 0 0" rpy="0 0 0" />
    <mass value="2.0" />
    <inertia ixx="0.000883" ixy="0" ixz="0" iyy="0.004333" iyz="0" izz="0.005083" />
  </inertial>
</link>
<joint name="right_shoe_weight_joint" type="fixed">
  <origin xyz="0.035 0 -0.01" rpy="0 0 0" />
  <parent link="right_ankle_roll_link" />

</joint>

<link name="head_weight">
  <inertial>
    <origin xyz="0 0 0" rpy="0 0 0" />
    <mass value="2.0" />
    <inertia ixx="0.006150" ixy="0" ixz="0" iyy="0.005417" iyz="0" izz="0.004067" />
  </inertial>
</link>
<joint name="head_weight_joint" type="fixed">
  <origin xyz="0.005 0 0.43" rpy="0 0 0" />
  <parent link="head_link" />
  <child link="head_weight" />

```

### 2.3 手の当たり判定

公式の手（`*_rubber_hand`）には当たり判定がありません。メッシュのままだと Gazebo が遅くなるので、メッシュを囲む箱を当たり判定にしました。

```python
for link in robot.findall('link'):
    if link.get('name', '').endswith('rubber_hand') and link.find('collision') is None:
        mesh = link.find('visual/geometry/mesh').get('filename')
        lo, hi = stl_bbox(src_meshes / Path(mesh).name)        # STL の外接箱
        col = ET.SubElement(link, 'collision')
        ET.SubElement(col, 'origin', {'xyz': ' '.join(f'{(a+b)/2:.4f}' for a, b in zip(lo, hi)), 'rpy': '0 0 0'})
        geo = ET.SubElement(col, 'geometry')
        ET.SubElement(geo, 'box', {'size': ' '.join(f'{b-a:.4f}' for a, b in zip(lo, hi))})
```

実際の追加内容（左手。右手は y の符号が逆）：

```xml
<collision>
  <origin xyz="0.0659 -0.0146 0.0102" rpy="0 0 0" />
  <geometry><box size="0.1318 0.0666 0.1065" /></geometry>
</collision>
```

### 2.4 ros2_control

29 関節すべてに、指令＝位置、状態＝位置・速度のインターフェースを付けます（`ign_ros2_control/IgnitionSystem`）。コントローラは講義と同じ 2 つ（`joint_state_broadcaster`・`joint_trajectory_controller`）で、名前は `g1_controller`、周期は 200 Hz です。

**追加の仕方**（`make_urdf.py`）

```python
joints = [j.get('name') for j in robot.findall('joint') if j.get('type') == 'revolute']
rc = ET.SubElement(robot, 'ros2_control', {'name': 'IgnitionSystem', 'type': 'system'})
hardware = ET.SubElement(rc, 'hardware')
ET.SubElement(hardware, 'plugin').text = 'ign_ros2_control/IgnitionSystem'
for name in joints:
    joint = ET.SubElement(rc, 'joint', {'name': name})
    ET.SubElement(joint, 'command_interface', {'name': 'position'})
    state = ET.SubElement(joint, 'state_interface', {'name': 'position'})
    ET.SubElement(state, 'param', {'name': 'initial_value'}).text = '0.0'
    ET.SubElement(joint, 'state_interface', {'name': 'velocity'})

gz_control = ET.SubElement(robot, 'gazebo')
plugin = ET.SubElement(gz_control, 'plugin', {
    'filename': 'ign_ros2_control-system',
```

## 3. お手本を作る

人のテレオペの代わりに、キーポーズを順に再生します。段の切り替えは、時間または回転角で決めます。

| 段 | 内容 | 次へ進む条件 |
|---|---|---|
| LEGS_UP | 手を耳の横・脚を上げる | 1.0 s（＋0.3 s 保持） |
| SLAM | 脚を床へたたきつける | 0.2 s |
| KICK | 脚を頭の上へ・腰を丸める | 回転角 ≥ 30° |
| FOLD | 脚をたたむ | 回転角 ≥ 70° |
| PUSH | 手で床を押す | 0.5 s |
| TUCK | 膝を抱える | 回転角 ≥ 260° |
| ZERO | 全関節 0（仰向けに戻る） | 1.0 s 保持 |

キーポーズの値を見つけるまでは、大きく 2 つに分かれます。①まず `pump3.py`→`kneel.py`→`land.py`→`roll360.py` と、porizou1 さんの Qiita 記事（https://qiita.com/porizou1/items/a085d20e936946330540 ）を参考に ChatGPT とスクリプトを書き換えながら、1 回転する動かし方を探しました。②見つかった動きを `moveit_roll.py`（MoveIt で滑らかにつなぐ版）に移し、値を変えながら 721 回試して、繰り返し回せる組み合わせを基準にしました。狙って作ったのではなく、たまたまです。

```bash
ros2 launch g1_gazebo g1_lying.launch.py gui:=true
ros2 launch g1_moveit_config moveit.launch.py      # コントローラ有効化・RViz
cd /workspace/g1_moveit_config/scripts
python3 moveit_roll.py roll                        # お手本を 1 回再生
```

## 5. 学習する

### 5.1 入力と出力（`g1_backroll_features_v2.py`）

| 項目 | 中身 | 次元 |
|---|---|---|
| `observation.state` | 29 関節の角度（`/joint_states`） | 29 |
| `observation.environment_state` | 回転センサから：骨盤から見た重力の向き 3・角速度 3・骨盤の高さ 1 | 7 |
| `action` | 29 関節の指令（`/roll/action`） | 29 |

回転センサの値を観測に入れるのがポイントです。お手本は回転角で次の段へ進むので、関節角だけでは「いつ次へ進むか」が分かりません。

学習の 1 サンプルでは、`observation.state`・`observation.environment_state` は今の 1 フレームだけですが、`action` は未来 50 フレーム分（`--chunk-size 50 --action-dt 0.02` → 0.02 s 刻みで 1 秒先まで）をまとめて取り出します。エピソードの終わりを超えた分は最後の値で埋め、`action_is_pad` を立てて学習時に無視します。

```python
def env_from_odom(qx, qy, qz, qw, wx, wy, wz, pz):   # 骨盤から見た重力の向き＋角速度＋高さ
    gx = -2 * (qx * qz - qw * qy)
    gy = -2 * (qy * qz + qw * qx)
    gz = -(1 - 2 * (qx * qx + qy * qy))
    return [gx, gy, gz, wx, wy, wz, pz]
```

### 5.3 学習（ACT・GPU）

```bash
cd ~/pai_training
pixi run python /workspace/pai_training_g1/scripts/train_g1.py \
  --dataset-root ~/dataset/lerobot_dataset/g1_backroll_v2 --repo-id g1_backroll \
  --output-dir /workspace/checkpoints/g1_backroll_act_v2 \
  --epochs 6 --chunk-size 50 --action-dt 0.02 --save-every 5000 --device cuda
# → 106,236 ステップ、RTX 4090 で約 75 分
```

- `--chunk-size 50 --action-dt 0.02`：0.02 s 刻みで 1 秒先まで（50 個）の指令を予測する
- `--save-every 5000`：途中経過を保存し、止まっても再開できる
- そのほかの ACT の設定は、学習済みモデルの `config.json`（実測値）で確認：
  - batch 2、学習率 `1e-05`（optimizer_lr・optimizer_lr_backbone とも。重み減衰 0.0001）
  - VAE あり（`use_vae`）・潜在変数 32 次元・KL の重み 10.0
  - Transformer：次元 512・8 head・encoder 4 層／decoder 1 層・`dim_feedforward` 3200・dropout 0.1
  - `vision_backbone`（resnet18）も項目としては残っていますが、画像を入力しないため使われていません

学習が終わると、`--output-dir` で指定した `/workspace/checkpoints/g1_backroll_act_v2/` に次のファイルができます（実物で確認済み）。

| ファイル | 中身 | サイズ |
|---|---|---|
| `config.json` | 上記の ACT の設定 | 約 1.3 KB |
| `model.safetensors` | 学習済みの重み（推論に使う本体） | 約 153 MB |
| `last/policy.pt` | `model.safetensors` と同じ重み（PyTorch 形式） | 約 153 MB |
| `last/resume.pt` | 重み＋オプティマイザの状態（学習を再開するための全部） | 約 307 MB |

`g1_backroll_act`・`g1_backroll_act_trim`・`g1_backroll_act_v2` の 3 つとも同じ構成でした。§6 の `roll2.py`（`MODEL = '/workspace/checkpoints/g1_backroll_act_v2'`）は、このフォルダを指定して `config.json` と `model.safetensors` を読み込みます。`last/resume.pt` は学習の再開専用で、デプロイ・推論には使いません（`policy.pt` との役割の違いはファイル名とサイズからの推測で、中身を比べたわけではありません）。

変換から学習・評価（5 回）までは、`bash /workspace/tools/after_v2.sh 6` でまとめて実行できます。

## 6. 学習したモデルで 2 回続けて後転させる

推論ノード（`roll_infer.py`）を `--gate` 付きで 1 回だけ起動し、`/roll/enable` で動かす・止めるを切り替えます。
1 回転して仰向けに戻ったら止め、1 秒待ってから 2 回目を始めます（2 回目はリセットしません）。

### 6.2 コード（`g1_moveit_config/scripts/roll2.py`）

```python
#!/usr/bin/env python3
"""学習済みモデル（g1_backroll_act_v2）で後転を 2 回続けて行う、シンプル版。

前提: 次の 2 つが起動済みであること
  ros2 launch g1_gazebo g1_lying.launch.py gui:=true
  ros2 launch g1_moveit_config moveit.launch.py
使い方:
  cd /workspace/g1_moveit_config/scripts && python3 roll2.py
動画は ~/deploy/g1_backroll_x2/roll_x2.mp4 に保存される。
"""
import os
import signal
import subprocess
import sys
import time

import rclpy
from builtin_interfaces.msg import Duration
from nav_msgs.msg import Odometry
from std_msgs.msg import Bool
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint

HERE = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, HERE)
import roll_trial as R  # noqa: E402  関節名 JOINTS・回転角 Roll・背骨の向き spine
from deploy_roll import raise_gazebo  # noqa: E402  Gazebo window to front

MODEL = '/workspace/checkpoints/g1_backroll_act_v2'
CFG = '/workspace/pai_training_g1/configs/g1_backroll_features_v2.py'
TIMES = 2                                   # 回数
OUT = os.path.expanduser('~/deploy/g1_backroll_x2')

rclpy.init()
node = rclpy.create_node('roll2')
pub = node.create_publisher(JointTrajectory, '/g1_controller/joint_trajectory', 10)
enable = node.create_publisher(Bool, '/roll/enable', 10)
st = {'t': None, 'q': None, 'ready': False}


def on_odom(m):                             # 回転センサ（骨盤の姿勢）とシミュレータ時刻
    st['t'] = m.header.stamp.sec + m.header.stamp.nanosec * 1e-9
    o = m.pose.pose.orientation
    st['q'] = (o.x, o.y, o.z, o.w)


node.create_subscription(Odometry, '/model/g1/odometry', on_odom, 50)
node.create_subscription(Bool, '/roll/ready', lambda m: st.update(ready=True), 10)


def wait(sec, until=None):                  # シミュレータの時間で sec 秒待つ（until が真なら途中で抜ける）
    while st['t'] is None:
        rclpy.spin_once(node, timeout_sec=0.1)
    end = st['t'] + sec
    while st['t'] < end:
        rclpy.spin_once(node, timeout_sec=0.02)
        if until and until():
            return True
    return False


def reset():                                # 全関節 0 → 骨盤を仰向けに置き直す
    msg = JointTrajectory(joint_names=R.JOINTS)
    msg.points.append(JointTrajectoryPoint(positions=[0.0] * len(R.JOINTS), time_from_start=Duration(sec=1)))
    pub.publish(msg)
    wait(1.5)
    subprocess.run(['ign', 'service', '-s', '/world/ground/set_pose',
                    '--reqtype', 'ignition.msgs.Pose', '--reptype', 'ignition.msgs.Boolean', '--timeout', '3000',
                    '--req', 'name: "g1", position: {x: 0, y: 0, z: 0.12}, '
                             'orientation: {x: 0, y: -0.70710678, z: 0, w: 0.70710678}'],
                   capture_output=True, timeout=10)
    wait(2.5)


def finished(roll):                         # 330° 以上回って、仰向け（腹が上）に戻った
    q = st['q']
    ang = roll(q)
    return (ang is not None and ang >= 330 and abs(R.spine(*q)[2]) < 0.3
            and 2 * (q[0] * q[2] - q[1] * q[3]) > 0.8)


# 1) 推論ノードを起動（--gate: /roll/enable が True の間だけ方策が指令を出す）
env = dict(os.environ, PATH=os.path.expanduser('~/.pixi/bin') + ':' + os.environ['PATH'])
infer = subprocess.Popen(['pixi', 'run', 'python', os.path.join(HERE, 'roll_infer.py'),
                          '--model-path', MODEL, '--config', CFG,
                          '--chain', '--n-action-steps', '10', '--gate'],
                         cwd=os.path.expanduser('~/pai_training'), env=env, start_new_session=True)

# 2) リセットし、モデルの読み込みが終わるのを待つ
reset()
limit = time.time() + 180
while not st['ready'] and time.time() < limit:
    rclpy.spin_once(node, timeout_sec=0.1)

# 3) 画面の録画を始める（画面全体）
os.makedirs(OUT, exist_ok=True)
raise_gazebo()
ff = subprocess.Popen(['ffmpeg', '-y', '-loglevel', 'error', '-f', 'x11grab', '-framerate', '15',
                       '-i', os.environ.get('DISPLAY', ':0'), '-vf', 'scale=960:-2',
                       '-c:v', 'libx264', '-preset', 'ultrafast', '-pix_fmt', 'yuv420p',
                       os.path.join(OUT, 'roll_x2.mp4')], stdin=subprocess.PIPE)

# 4) 2 回続けて後転（2 回目はリセットせず、1 回目の終わりの姿勢から始める）
for i in range(1, TIMES + 1):
    roll = R.Roll(st['q'])                  # この回の始まりの向きを 0° とする
    enable.publish(Bool(data=True))
    ok = wait(8.0, until=lambda: finished(roll))
    enable.publish(Bool(data=False))
    wait(1.0)                               # 姿勢が落ち着くのを待つ
    print(f'roll {i}: {"SUCCESS" if ok else "fail"}  {roll(st["q"]) or 0:.1f} deg', flush=True)
    if not ok:
        break

# 5) 後片付け
wait(1.5)
ff.communicate(b'q', timeout=15)            # q を送って録画を正しく閉じる
os.killpg(infer.pid, signal.SIGINT)
rclpy.shutdown()
```

回数を変えるときは `TIMES` を変えます。録画の大きさやカメラの追従など、より細かい設定がある版は `roll3.py`（`--times N`）です。
